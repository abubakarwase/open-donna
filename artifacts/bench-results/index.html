Measurement limits

  • Run on a 16 GB machine. The 8 GB result is the RSS rule above, not a run on 8 GB hardware.
  • Peak RSS is sampled with ps during the golden run. Physical footprint (vmmap / footprint) was not measured. gemma4-e2b peak RSS (2.93 GB) is below its file size (3.11 GB) because the model is memory-mapped and not every page was resident.
  • qwen3.5-4b peak RSS is 3.48 GB, 24 MB under the 3.5 GB budget.
  • phi4-mini returned no native tool calls through llama.cpp with --jinja. It answered with prose or pseudo-code (see raw/phi4-mini.jsonl), so all its tool scores are 0.
  • functiongemma-270m was scored on router cases only.
  • Golden set is small (15 router, 15 tool, 10 SQL). SQL is scored by DuckDB execution match against fixtures/sales.csv.
  • UI cold start signal differs: A fires after React commits the table rows; B fires at the first GPUI render, before paint. Caches were not purged; A runs before B. First-run values: A 1.88 s, B 0.48 s.
  • UI RSS for A = app process tree + WebKit helper processes that did not exist before launch (3 per run).
  • Input latency and frame timing were not measured.
